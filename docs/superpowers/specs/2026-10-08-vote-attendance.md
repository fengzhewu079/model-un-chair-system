# 投票出勤更新边界

用户确认：新一轮采用最新出勤；本轮投票固定开始时名单，变更后由主席主动更新，历史结果不重算。

- 普通动议投票保存本地、按房间/组隔离的名单快照。人数、门槛只随主席点击 Update attendance 改变。重进保留名单快照；未确认的普通动议票数仍沿用原页面行为，不新增跨页面持久化。
- 决议投票保留原有逐篇本地草稿，检测人数、名单和 P/PV 变化，显示 Attendance changed。Refresh attendance 只更新当前篇名单，清除离场代表的个别票和新 PV 身份禁止的弃权；手输汇总数保持原值，超出更新后人数则原有校验提示纠正。
- Next paper 使用最新出勤；此前已确认篇目和历史记录保持原快照。
- GSL、Moderated Caucus、Speaker List、Round Robin 的当前/等待发言人可标记 Absent 并手动跳过，保留已完成发言记录。自由输入且不匹配代表的名字不强行判定缺席。
- 保留现有后端出勤保护：存在执行中动议/处理草稿时仍须先结束执行才能修改出勤。本次没有修改 RPC、数据库权限或取消这项限制。

验证：67 项测试及生产构建通过。独立本地 React 测试页使用实际组件模拟出勤变化，亲自验证普通投票保持人数/票数、主动刷新、名单重进恢复、P 转 PV 的提示/刷新后清除禁止弃权、GSL 缺席标记和 Skip。真实多人 RPC 与联网同步未实测。仅修改预览分支，不部署正式站。
